# Changelog

## Unreleased

- **Chats stopped at the 5-hour limit with Claude Code 2.1.312:** Claude now calls it the *5-hour limit* (before, the *session limit*), and such a stop wasn't tied to the account's 5-hour window: its bar didn't show it full, and *Go on at …* and **Keep going** guessed the reset from the message. Both names work now, and the reset Claude notes with the stop comes first, so a shared chat that another account's limit stopped no longer fills this account's bar (also in *Recent chats*) and goes on when that account's limit resets.
- **Keep going waits when nobody knows when the limit resets:** out of usage credits, or a limit Claude dates more than a day out (*resets Oct 30, 7pm*), a chat that keeps going went on again every few seconds, each time adding a go-on and a limit error to the chat, and a notification. Dates in Claude's message are read now; with no reset to go by, it tries again after 2, 5, 15, 30 and 60 minutes, then gives up and says so.
- **The Permissions tab no longer suggests rules that let more through than they say:** *Allow “rg”*, *“tree”*, *“git branch”*, *“git diff”*, *“git log”* and *“git show”* let a chat run those with any options, and some options run another program (`rg --pre`), write any file (`git diff --output=…`, `tree -o`) or delete a branch (`git branch -D`), all without asking. They aren't offered any more; rules you added with them stay until you revoke them.
- **Allow and Deny answer what the chat asks now:** after you answered a permission prompt in the chat and it asked again right away, the popup, the chat pane, the notification and Meta+Alt+Y/N could still offer the first prompt, and Allow or Deny there went nowhere, though it said *Allowed* or *Denied*. They show the newest prompt now, and an answer to one the chat asked again after isn't taken: you're told it asks something else now (Plasma and VS Code).
- **The next permission prompt gets its notification:** when a chat asked again within a minute of its last prompt (you allowed a command, and it asked for the next), no notification came, so no Allow or Deny buttons and no sound, and only the panel icon blinked for as long as it waited. Only the same prompt asked again is held back now (Plasma, GNOME and VS Code, where it came a check later without a sound, and the same prompt could come twice).
- **Your replies arrive whole:** a message from the chat pane (or one queued for after the turn) to a chat in VS Code's Claude was cut off at an `&`, and a `+` in it became a space; one of a few thousand characters to an SSH host's chat (fewer with accents, quotes or a non-Latin script) didn't fit in the one ssh command that carries it, and wasn't sent. A reply reaches the chat as you wrote it now, a long one for a host going over first, into a file private to you that's removed once read (Plasma and VS Code).
- **Two replies typed into tmux chats at once go each to its own chat:** both went through one shared paste buffer, so one chat could get (and run) the other's message while the other got *no buffer*. This was likeliest with two messages queued for after the turn, or a reply sent while plan feedback was typed.
- **A new VS Code chat about a long plan opens:** a plan of some 90 KB (a third of that in a non-Latin script; on an SSH host any size) made the link handed to VS Code longer than one command-line argument may be, and no chat opened, though the widget said it would. The plan is cut at a line now, saying it goes on in its file, as for a terminal; a task too long by itself says so.
- **Disconnect leaves your terminals open:** disconnecting from an SSH host also ended the chats you had open in terminals over that connection. Now nothing new uses the connection, and it closes once the last of those terminals does.
- **SSH hosts whose login shell is fish or tcsh:** what the widget runs there went through that shell's own quoting first, so a prompt, a folder or a picture with a backslash, a newline or a `!` (and with tcsh every pasted picture) failed or arrived changed. Commands now reach `sh` there in a form every shell passes on as it is (Plasma and VS Code).
- **Make default keeps every account listed:** when `~/.claude` linked to an account's folder with another name (say `~/accounts/work`), making another account the default dropped that one from every list, with no word. It now says so instead, until that folder is among the extra config folders in the settings.
- **The same words in Plasma, GNOME and VS Code:** an account with nothing running reads *No running chats*, the hero *No chats running*, and removed chats come back with *Show removed chats again* (the word was *sessions* in Plasma and GNOME, *chats* in VS Code). The panel icon's right-click menu is in title case throughout (*Show Removed Chats Again* read *Show removed sessions again* beside *Go to the Chat That Needs You*). The files-changed tag reads *±3* everywhere (*± 3 files* in GNOME and VS Code), with *3 files changed* over its list. VS Code shows an account's tokens as the widget does (*Tokens today 378.3k (12.0k out) · 7 days 502.9k (15.0k out)*; the week's two biggest models, cut off in a narrow sidebar, are in its tooltip), says how old the plan usage is in a dim line under the bars (*Plan usage as of 5m ago*, not *usage updated …* in the account's heading), colors a chat's state words only when it needs you or a usage limit holds it (the dot carries every state's color), and hides a finished chat with a − (it was the × that cancels a queued task).
- **GNOME shows the chats a usage limit stopped:** such a chat read *Idle · 5m* with a green dot, like a healthy one, and counted as idle or done, so the hero said *Your turn in 1 chat* (or *1 finished chat to look at*) though it couldn't go on before the reset. It reads *Limit · resets in 2h 3m* (or *Login expired*) with a red dot now, and the hero says *1 chat waits for its usage limit*, with a red *1 at the usage limit* among the counts and in the header's summary, as in Plasma and VS Code.
- **GNOME shows an account's plan usage once:** an account on this computer and on an SSH host had two sets of bars there, each machine's own (the host's often hours old). It shows them where the account is listed first, with the newest numbers of them all (*Plan usage as of 5m ago, on lab*), as Plasma and VS Code do by default.
- **The focus view lists the chats that finished:** in Plasma its *Finished: results to look at* lines were cleared the moment the popup opened, so they never showed and those chats only counted under *Also: … done*; in VS Code they listed every chat whose turn ended in the last 15 minutes, also ones you had opened, and left out failed ones. Both list the chats that finished a turn you haven't looked at yet now, newest first and failed ones too (*Failed: look at what happened*), until you open that chat (its pane, tab or window). *New chat here* on the Projects tab, or a project folder picked in the search, opened its box in a part of the popup the focus view hides, so nothing seemed to happen; they show everything now, with the box open.
- **Claude's replies show as Claude wrote them:** in the chat pane, globs and arguments such as `*.py and *.js`, `*args` or `**kwargs` lost their asterisks and turned part of the reply italic or bold; a `\|` in a table split its cell in two with the backslash showing, and `\*` showed its backslash; a code block under a numbered step was shown and copied with the step's indentation on every line, so pasted Python or YAML came out indented wrong; and a link to a page with parentheses in its address (Wikipedia's *C_(programming_language)*) opened a cut-off address and left a stray `)` after its text. They show and copy as written now (Plasma and VS Code). In a VS Code chat tab, a numbered list with bullets under a step numbered the bullets too, and the next step got a later number (*1. Step one, 2. detail, 3. detail, 4. Step two*); the bullets are a list of their own under their step now, and a bare `https://` address is a link there too.
- **The chat pane keeps what you type for each chat, and sends it once:** opening another chat in the pane threw away the reply you were typing, pictures and all; it's back in the box when you return to that chat now. A Deny note begun for one chat no longer turns up in the next chat's prompt, and dictation started for one chat no longer writes into the next one's box (words still being written down go to the chat they're for). An Enter again, or a click on *Send*, before the first message had gone sent it twice (typed into tmux twice, or the chat resumed twice); the buttons wait now (*Sending…*), and what you type meanwhile stays in the box.
- **The chat pane stays where you were:** after a look at *Review* or *Output*, the chat showed an earlier part and stopped following new steps. Back on *Chat*, it's at its end and follows it again if it was when you left (Plasma and VS Code; VS Code also keeps your place further up). Scrolling up just after a new step came in no longer pulls you back to the end. *Show earlier* past the 2000th step stayed and did nothing; a note says only the last 2000 steps are shown there now (Plasma and VS Code).
- **Plans in the chat pane:** *Read the whole plan* (a plan too long to show) did nothing; it opens the plan's file now. Its buttons come in Claude's own order, as in VS Code: *Approve, accept edits* first (the main one, in bold), then *Approve*, then *Keep planning…*.
- **The chat pane's text size covers what Claude asks and the Review tab:** with the pane's text larger (*A+*, Ctrl+wheel; 115 % by default), a permission prompt, a plan, Claude's questions and the Review tab's files and commit message stayed at the desktop's size, half the chat's at 200 %. - **Undo and Commit in the chat pane's review:** Undo brought a file the chat deleted (and its folder) back private to you, so a script came back not executable; it comes back as git has it, with your usual permissions. *Commit* also committed your own changes to files that a chat's file name matched as a pattern (`app/[id]/page.tsx`, `a[1].txt`); names are taken as they are now.
- **Compare in VS Code shows what the review shows:** a file Claude keeps no copy of (one outside the chat's folder, say) has its earlier version in what the chat's first edit of it gave back; the pane's review used that, but *Compare in VS Code* asked git only, so it left such a file out or said it had *no earlier version to compare with* (Plasma and VS Code).
- **The chat pane counts an edit's lines right:** a changed line starting with `--` or `++` (a Markdown rule `---`, YAML front matter, `++i`) wasn't counted, so an edit could say *1 line removed* for one line added and two removed.
- **Always allow for an edit in a tmux chat:** Claude's dialog for an edit offers *Yes, allow all edits during this session* rather than *Yes, and don't ask again*, so *Always allow* from the popup or the pane said *That answer isn't one of the choices it shows*. ## 1.16.1 (2026-10-27)

- **The widget no longer stops refreshing:** a status check that lost its answer could still leave the popup and the panel showing what they saw last, **Refresh** too, until plasmashell restarted: what 1.16.0 does with such a check failed on it at each try (*a check didn't start* in the journal, every few seconds). Such a check now runs again at the next check instead of a minute later, and nothing can keep it from running.
- **Refresh while a check runs checks again:** a click while a check was running did nothing; now another check runs right after it, so what you just did (stopped a chat, queued a task) shows. A check asked for because a chat changed while one ran is now really run too: it got the answer of the check before back from Plasma, so the change showed only at the next check.
- **Less work each time a chat changes:** the watcher that notices a chat start, end, work or wait (and with live mode, each step it takes) got its own answer back from Plasma about 90 times in a row after each change, each a status check for every copy of the widget. It now answers once per change (Plasma).
- **No error when a chat's pet digs away:** each pet that left after its chat ended put two errors in the journal (*attempted to evaluate a function in an invalid context*, *TalpyView.qml:121: … 'showWanted' … is not a function*): it was taken off the stage in the middle of drawing its last picture. It's now taken off right after (Plasma).
- **GNOME Shell 43 and 44 again:** `./install.sh` stopped there with *the GNOME 43 port needs updating* since the Recap's history setting came: its converter knew only one switch row in the settings, and libadwaita 1.2 has no `Adw.AlertDialog` for *Delete…*. It builds again (the history's *Delete…* asks with libadwaita 1.2's own dialog there), and the tests on GitHub build the GNOME 43/44 version too, so it can't break unnoticed again.
- **`install.sh` builds the GNOME extension before it replaces anything:** it took out the extension of the first name (Claude Status) first, so a build that failed, or a GNOME Shell it doesn't run on (45 to 48), left you with no extension at all. Now the old one stays until the new one is built.
- **The numbers in GNOME 43's settings show whole:** *…while nothing runs* showed *1000* for its 10000 ms, cut off; the settings window there makes room for each number's longest value.
- **A quiet GNOME log, and Talpy's first words where they belong:** on GNOME 43, each refresh of the open popup logged some 40 *Can't update stage views … needs an allocation* warnings (the usage bars were sized while they were laid out) and the pets *st_widget_get_theme_node called on the widget … which is not in the stage*. The bars are laid out with the popup now, and the pets measure their stage only while it's shown. Talpy's *Hi!* as the popup first opened showed at its left edge; it waits until it can stand over Talpy.
- **Answering from the widget and live mode on Debian and Ubuntu:** their `sh` is dash, which Claude runs hooks with, and dash stays between Claude and the hook, so the permission hook gave up after 5 seconds (no Allow or Deny from the widget) and live mode never showed a step. The hooks find their Claude through the shell now, and run with `exec` (and a quoted path: a home folder with a space in its name broke them too). - Half an emoji in a chat's title (or anything else that can't be written as UTF-8) made every check fail; the status is written as ASCII JSON now.
- A shared chat could be hidden as "moved on" when a copy of it was open somewhere; a chat that moved on to a listed session no longer shows under *Recent chats* too.
- Subagents that ended on an API error (e.g. a usage limit) or were interrupted showed as *running · writing…* until their chat ended: they show as *failed* (in red) or *stopped*, and one Claude marks as finished is done. A fork no longer counts the call that started it (its parent's reply and tokens) as its own work, and an agent the chat sends more work shows as running again.
- Several copies of the widget (panel and tray, the GNOME or VS Code extension) no longer throw away each other's cache entries and token caches, which made them read big transcripts from the start again; a copy with other settings no longer forgets your removed sessions either, and removing one while a check runs isn't lost.
- An old copy of a background session's record (left behind by a link switch) could show as *needs you* forever; one odd record or status-line snapshot no longer hides all of an account's background sessions; one odd transcript line no longer empties *Recent chats* or the token totals.
- Two profiles of one account sharing a chat counted its tokens twice. The 1-hour usage forecast now takes the real time since its last point; a clock set back no longer stops token scans; snapshots are pruned with token totals off too.
- Plasma: chat names, agent activity and other text from transcripts are shown as plain text (as rich text, an `<img>` in an agent's activity made Plasma fetch it); notification texts are escaped. Clicking a *Couldn't open* notification opens the popup instead of another error; a failed action on an SSH host notifies when the popup is closed. A host that stopped answering no longer keeps the badge, tray status and shortcut busy with its old chats, and unticking a host forgets them (no burst of "finished" when you pick it again). A host's clock being off no longer skews its times. A chat's notifications and "seen" follow the chat, not its row: a background session whose row changes from running to finished still notifies, and one listed twice no longer alerts every minute.
- Plasma: the usage bars (and their forecast tooltip) no longer rebuild every check; the settings dialog no longer puts back hosts or the VS Code switch changed in the popup meanwhile, shows the phone you picked, and the volume slider goes in whole steps; the icon stops pulsing once you've opened the popup; hosts picked together are all checked at once; no Interrupt for a chat whose turn is over.
- Pets: a pet turned around mid-walk no longer walks on looking like it stands still, a chat's pet no longer vanishes without walking off, one grabbed while falling or leaving behaves, and they keep their spots when the list changes; no particles pile up while the popup is closed; same chat on two accounts, two pets; less work per check.
- GNOME: the "while you were away" notification was closed right after it showed; a hung check no longer stops the checks for good; a failed start leaves nothing behind; the shortcut needs a modifier key; and the same fixes as on Plasma for hosts, notifications and agents.
- `install.sh`: the "add the snippet by hand" hint now shows when no status line is found; status lines run as `bash $HOME/…` or without `.sh` are found; the script is replaced in one step (Claude never runs it half-written), with a clear message when it can't be written; GNOME Shell 45–48 are refused before anything is installed; `--uninstall` keeps the snippet while another front end uses it. The snippet itself can no longer stop a status-line script that uses `set -e`.
