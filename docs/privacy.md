# Privacy

- Talpy Den reads the files Claude Code writes, on your computer and on the SSH hosts you pick (through your own SSH login). It never handles your SSH password: you type it into `ssh` itself, in a terminal, and nothing of it is stored. On an SSH host it also reads which account VS Code's Claude uses there (the VS Code server's settings), and changes only that one setting (`claudeCode.environmentVariables`' `CLAUDE_CONFIG_DIR`), when you start a VS Code chat there on another account. Besides those it reads only your `~/.ssh/config` host list, the desktop settings it needs (default terminal, sound theme, Do Not Disturb) and process and window info (`/proc`, Konsole, tmux, KWin) to find where a chat runs (and, for a widget on the desktop, where your windows are, to rest the pets while one covers it); of a Claude process's environment it keeps only `CLAUDE_CONFIG_DIR` and `HOME`. To know which account VS Code's Claude uses, it reads `CLAUDE_CONFIG_DIR` from VS Code's settings (`claudeCode.environmentVariables`) or from VS Code's environment, nothing else. It never opens Claude's credentials (`.credentials.json`, the system keyring; it only looks whether `.credentials.json` is there before it asks Claude Code for an account's plan usage); of `.claude.json` it reads only what's listed above. When `claude` isn't on the desktop's PATH or in the usual install folders, a click on a chat runs your login shell once (`$SHELL -l -i -c env`) to read the PATH it sets up, nothing else.
- It calls no Anthropic API itself and sends no data anywhere. When an account's plan usage is more than 5 minutes old while one of its chats works (in Claude's VS Code panel, which runs no status line), it asks Claude Code for it, at most every 5 minutes per account (*Fetch plan usage older than* in the settings sets those minutes; 0 turns it off): `claude -p /usage` on that account, with hooks off and no chat saved, which fetches it from Anthropic the way `/usage` does and keeps it in the account's `.claude.json` (it uses no tokens). Nothing about your chats is sent. It runs in `~/.cache/talpy-den/usage-check` and isn't listed as a chat; `~/.cache/talpy-den/usage-check.json` notes when it last ran for each account. *Open Usage Page on claude.ai* just opens that page in your browser. Setting up dictation downloads faster-whisper from pypi.org (with `pip`) and a speech model from huggingface.co, and downloading another model does the same: plain downloads that send nothing about you or your chats. With the Recap tab's amounts in a currency other than US dollars, the tab downloads the European Central Bank's public exchange rates (`https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml`) at most every 6 hours while it's open: a plain download that sends nothing about you or your chats. A task you start a chat with goes to Claude, which runs it like a prompt you type (with a plan you carry out, the plan's text is part of it); so does feedback on a plan you send (what you changed in it), which Talpy Den puts on your clipboard when it can't type it in. The one exception is the *Phone* setting (off unless you turn it on): then a chat's name, what it needs and its folder go to your phone through KDE Connect.
- Everything it stores lives in `~/.cache/talpy-den` (tasks you queue too, with their text, until they start), plus shared chats' folders in `~/.local/share/claude-status/shared-chats`; only your user can read either (mode 0700). `~/.local/share/talpy-den` holds the hooks' scripts (`permission-hook.py`, `live-hook.py`) and, once you set dictation up, its speech engine and models (`whisper/`: about 600 MB, more with each bigger model). SSH connection sockets go to `$XDG_RUNTIME_DIR/talpy-den-ssh`, which is cleared when you log out. Its JSON output replaces account ids with a one-way hash.
- It changes Claude Code's files only when you share a chat or a plan, when you **Allow…** a rule in the Permissions tab (one entry of `.claude/settings.local.json` in the folder its chats started in; **Undo** takes it back, and `~/.cache/talpy-den/rules.json` remembers what it added) or **Revoke…** one of the permissions you gave (that entry of the settings file it's in) (here, or between an SSH host's accounts on that host): it links the chat (with its plan) or the plan into your other profiles, or out of them again; and when you add or remove an account in its settings (see [Accounts](usage.md#accounts)): it makes the `~/.claude-NAME` folder (its `.profile-name` and the links to the settings you share) and the `~/.local/bin/claude-NAME` command, or moves the folder to the Trash. **Make Default** changes the `~/.claude` link (when it is one) and one entry of VS Code's settings (`claudeCode.environmentVariables`' `CLAUDE_CONFIG_DIR`; on an SSH host, its VS Code server's), nothing else of them. The same happens on an SSH host when you manage its accounts. Logging in and out is Claude's own `claude auth login` / `logout`; the Accounts page asks `claude auth status` whom each account is logged in as, and shows its email address only there. Before a removed folder goes to the Trash, Talpy Den deletes its `.credentials.json` without opening it, so no login ends up in the Trash.
- With **Live mode** on, the live hook writes each chat's last steps to `~/.cache/talpy-den/live/<session>.json` (the tool and its file name or command, cut to 60 characters, and the first line of Claude's last reply); a file goes once its chat has said nothing for 3 days. Turning live mode off takes the hook out of `settings.json` again.
- The chat pane reads the chat's transcript. What you send goes to Claude as your message; an answer to a permission prompt (or to Claude's questions) goes to Claude through the hook (*Answer permission prompts from Talpy Den*: it's `~/.local/share/talpy-den/permission-hook.py`, named in each profile's `settings.json`; it writes each request to `~/.cache/talpy-den/permissions` while it waits, and removes it once answered) or as the dialog's keys in tmux. **Undo** writes the files back as they were before the chat (a file it made is removed), **Commit** runs `git add` and `git commit` on only the chat's files, and **Mark reviewed** is kept in `~/.cache/talpy-den/reviewed.json`.
- To show what a chat changed, it reads Claude's backups of the chat's files (`file-history/`) and the files themselves, runs `git show HEAD:<file>` for a file with no backup, and puts copies of the earlier versions in `~/.cache/talpy-den/changes` for VS Code to show; they're removed after a day. A subagent's run you open is written to `~/.cache/talpy-den/agent-runs` (an SSH host's comes over your ssh connection) and opened with `xdg-open`; it's removed after a day too. It also reads Claude's task lists (`tasks/`), plans (`plans/`; an SSH host's plan you open comes over your ssh connection and is written to `~/.cache/talpy-den/agent-runs`, removed after a day) and memories (`projects/<folder>/memory/`), and each account's `CLAUDE.md`; it changes none of them itself (✎ opens the file in your editor). It asks the screen saver over D-Bus whether the screen is locked.
- It uses the microphone only while you dictate (the chat pane's **Dictate**, until you click it again, five minutes at most): the recording goes to `~/.cache/talpy-den/dictation` (only your user can read it), is written down on this computer, and is deleted right after (one left behind, say by a pane closed while it recorded, after an hour). What you said goes into the reply box; nothing is sent until you send it.
- It reads the clipboard only when you press Ctrl+V in a new chat's task field or the chat pane's reply box and there's no text to paste: a picture there is saved in `~/.cache/talpy-den/images` for the chat to open (only that folder is added to a chat it starts or that goes on in the background, `claude --add-dir`), and deleted after 30 days. For an SSH host's chat it's copied to the host's `~/.cache/talpy-den/images` only once you click **Copy**, and deleted there after 30 days too.
